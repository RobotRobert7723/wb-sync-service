# wb-sync-service

`wb-sync-service` — сервис загрузки данных из Wildberries API в PostgreSQL.

Проект рассчитан на самостоятельное развёртывание пользователем на Ubuntu VPS в отдельном Docker-контейнере. После установки сервис автоматически создаёт production-схему `wb_prod`, запускается в фоне и ждёт настройки магазинов в таблицах БД. Как только пользователь добавляет токены и включает воркеры, начинается загрузка данных.

## Что умеет первая версия

- загружает `orders` и `sales` из WB Statistics API;
- поддерживает несколько магазинов в одном сервисе;
- запускает отдельный поток на связку `магазин + API`;
- автоматически перечитывает настройки из БД без рестарта;
- хранит данные в PostgreSQL в production-схеме `wb_prod`;
- сохраняет статусы, курсоры, heartbeat и историю запусков;
- выполняет идемпотентный upsert без дублей при повторной загрузке одного диапазона.

## Основной сценарий

1. Клонировать репозиторий на Ubuntu VPS.
2. Запустить `./install.sh`.
3. Ввести параметры подключения к PostgreSQL.
4. Дождаться, пока установщик создаст схему `wb_prod`, соберёт контейнер и поднимет сервис.
5. Добавить магазины и воркеры в таблицы `wb_prod.wb_accounts` и `wb_prod.wb_sync_workers`.
6. Убедиться, что загрузка стартовала и данные появились в `wb_prod.wb_orders` и `wb_prod.wb_sales`.

## Быстрый старт для разработчика

Локальный запуск по-прежнему доступен:

```powershell
$env:WB_SYNC_PG_DSN="postgresql://user:password@host:5432/dbname"
$env:WB_SYNC_DB_SCHEMA="wb"
python -m wb_sync.main init-db
python -m wb_sync.main run
```

Если `WB_SYNC_PG_DSN` не задан, можно использовать раздельные переменные:

```powershell
$env:WB_SYNC_PG_HOST="127.0.0.1"
$env:WB_SYNC_PG_PORT="5432"
$env:WB_SYNC_PG_DATABASE="postgres"
$env:WB_SYNC_PG_USER="postgres"
$env:WB_SYNC_PG_PASSWORD="secret"
$env:WB_SYNC_DB_SCHEMA="wb"
python -m wb_sync.main run
```

## Production-схема

Для production используется схема `wb_prod`.

Текущая схема `wb`, которая использовалась во время разработки, считается dev-схемой и не должна использоваться в production-развёртывании.

## Текущее покрытие API

В первой версии поддерживаются только:

- `orders`
- `sales`

Для этих методов сервис сохраняет все поля, доступные на сегодня в актуальной документации WB API. Если WB добавит новые поля, потребуется расширение схемы и маппинга.
